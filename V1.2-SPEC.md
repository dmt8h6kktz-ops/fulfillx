# FulFillX — V1.2 Specification (Phased Build)

Builds on V1.1. Same rules: single self-contained `FulFillX.html` (HTML + CSS + JS inline,
no build step, no deps except Google Fonts), all data in `localStorage`, no backend.
Runs by double-clicking. Slate (light) / Graphite (dark) themes and Baloo 2 / Fredoka
typography are already in place from V1.1 — reuse the existing CSS variables; do NOT
restyle.

## HOW TO BUILD THIS (read first)
Execute the four phases below **in order, one at a time**, with targeted/incremental edits.
Do NOT rewrite the whole file in one response. After each phase: confirm its acceptance
criteria, summarize what changed and how to verify it, commit ("V1.2 Phase N: <name>"),
then continue. Never break or discard existing `localStorage` data — migrate it.

## THEME / GOAL OF V1.2
Make the Habits tab a real, functional habit scheduler, and make the journals
schedule-aware. Habits become first-class objects with their own time-of-day and
day-of-week schedule. Each journal's habit checklist is then generated from the habits
scheduled for that time slot on that weekday — so the user is effectively planning a
weekly schedule that surfaces the right habits at the right moments.

## HABIT DATA MODEL (`localStorage` key `fulfillx.habits`)
An array of habit objects:
```
[
  { "id": "h_reading",   "name": "Reading",        "icon": "📖", "slots": ["evening"],            "days": [0,1,2,3,4,5,6], "active": true },
  { "id": "h_meditate",  "name": "Meditation",     "icon": "🧘", "slots": ["morning"],            "days": [0,1,2,3,4,5,6], "active": true },
  { "id": "h_exercise",  "name": "Exercise / Gym", "icon": "💪", "slots": ["daytime"],            "days": [1,3,5],         "active": true },
  { "id": "h_language",  "name": "Language study", "icon": "🗣️", "slots": ["evening"],            "days": [0,1,2,3,4,5,6], "active": true },
  { "id": "h_walk",      "name": "Walk",           "icon": "🚶", "slots": ["daytime"],            "days": [0,1,2,3,4,5,6], "active": true }
]
```
- `slots`: any of "morning" | "daytime" | "evening" (a habit may appear in more than one).
- `days`: day-of-week numbers, JS convention 0=Sunday … 6=Saturday. UI shortcuts
  "Every day" = [0..6], "Weekdays" = [1,2,3,4,5], "Weekends" = [0,6].
- `active`: false = soft-removed (hidden everywhere) but kept for history.
- Habit completion is tracked per habit per DATE, independent of slot, so checking a habit
  in any journal reflects everywhere: store under `fulfillx.entries[date].habits = { "h_reading": true, ... }`.

## PHASE 1 — Habit model + seed + migration
- Add the `fulfillx.habits` model. On first run (no existing key), seed the five
  data-backed defaults above.
- MIGRATION: if a prior V1.1 install has habit items inside `fulfillx.config`
  (morning `habits-am.config.items`, evening `habits-pm.config.items`), convert each
  distinct item into a habit object — morning items get `slots:["morning"]`, evening items
  get `slots:["evening"]`, an item appearing in both gets `slots:["morning","evening"]`,
  default `days` = every day, `active:true`. De-duplicate by name. Run migration once.
- Preserve any already-recorded habit checkmarks where reasonably possible; if not
  mappable, leave past days as-is and start clean going forward (never crash).
Acceptance: `fulfillx.habits` exists and is seeded or migrated; no data loss; app still
loads and journals still open.

## PHASE 2 — Schedule-aware journals
- Change the `habits` widget type so it no longer renders a static list. For a given
  journal slot S (morning/daytime/evening) on today's weekday W, it renders every habit
  where `active && slots.includes(S) && days.includes(W)`, each as a checkable item
  (show the icon + name).
- Checking/unchecking writes to `fulfillx.entries[date].habits[habitId]`; the same habit
  shown in two slots stays in sync for that date.
- If no habits are scheduled for that slot/day, show a small muted line like "No habits
  scheduled — add some in the Habits tab."
- Daytime: if it currently has no habits widget, give it one too so daytime-scheduled
  habits can appear there. Keep Daytime otherwise minimal.
Acceptance: each journal shows exactly the habits scheduled for its slot and the current
weekday; completion persists and stays in sync across slots; empty state shows when
nothing is scheduled.

## PHASE 3 — Habits tab manager
Rebuild the Habits tab into a manager (reuse existing card/theme styles):
- "Your habits" list: each active habit shows icon + name + a schedule summary line, e.g.
  "📖 Reading · Evening · Every day" or "💪 Exercise / Gym · Daytime · Mon, Wed, Fri".
- Add habit: a form/sheet with name, optional icon (a small emoji picker or text field),
  time-of-day multi-select (Morning / Daytime / Evening), and day-of-week selection with
  the Every day / Weekdays / Weekends shortcuts plus individual day toggles. Saving appends
  to `fulfillx.habits`.
- Edit habit: same form, pre-filled; updates the object.
- Remove habit: set `active:false` (soft delete) with a confirm; it disappears from the
  list and journals but history is retained.
- All changes write to `fulfillx.habits` and reflect immediately in the journals.
Acceptance: can add, edit, and remove habits with full slot + day scheduling; the list
shows accurate schedule summaries; journal checklists update to match immediately.

## PHASE 4 — Suggested habits + polish
- "Try a new habit" section in the Habits tab, seeded from this data-backed pool (from the
  user's own archive): Reading, Running, Exercise / Gym, Walking, Meditation, Breathwork,
  Language study, Journaling, Stretching. Each shows name + a sensible default slot, with a
  "Try" button that adds it to `fulfillx.habits` with a default schedule (every day, a
  sensible slot) which the user can then edit. Don't duplicate habits already active.
- Do NOT pre-seed sensitive behavior-change items (e.g. alcohol/sobriety, diet/calorie
  tracking). The user can add their own if they choose; the app must not surface these by
  default.
- Light Insights touch: add a simple "habit consistency this week" readout (e.g. % of
  scheduled habit-instances completed over the last 7 days, or a per-habit count). Keep it
  small; no heavy charts.
- Tidy empty states and confirm everything still works in both Slate and Graphite.
Acceptance: suggestions add real scheduled habits without duplicates; no sensitive habits
seeded by default; a basic weekly habit-consistency readout appears in Insights; both
themes intact.

- Mobile-first; verify in Chrome device mode (Cmd+Shift+M) at iPhone width, both themes.
