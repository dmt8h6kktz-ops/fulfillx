# FulFillX — V1.3 Specification (Phased Build)

Builds on V1.2. Same rules: single self-contained `FulFillX.html` (HTML + CSS + JS inline,
no build step, no deps except Google Fonts), runs by double-clicking. Slate (light) /
Graphite (dark) themes, Baloo 2 / Fredoka type, the widget engine (V1.1), and the habit
scheduler (V1.2) are already in place — reuse them; do NOT restyle or rebuild them.

## HOW TO BUILD THIS (read first)
Execute the six phases below **in order, one at a time**, with targeted/incremental edits.
Do NOT rewrite the whole file in one response. After each phase: confirm its acceptance
criteria, summarize what changed and how to verify it, commit ("V1.3 Phase N: <name>"),
then continue. Never break or discard existing `localStorage` / `IndexedDB` data — migrate
it. If a phase can't be completed cleanly, stop and explain.

## GOAL OF V1.3
Extend FulFillX from a journal into a daily companion: add a to-do/day-planner, an
all-day quick-access to-do button, optional reminders, photo attachments, a browsable
History calendar with the ability to fill in missed days, a home week strip, and a
verified daily-quote set.

## DATA MODEL ADDITIONS

### To-do items (live inside journal entries via two new widget types)
Two new widget types in the existing widget engine:
- `checklist` — simple tasks, each `{ "text": "...", "done": false }`.
- `schedule` — day planner; each item `{ "text": "...", "time": "15:00" | null, "done": false,
  "reminder": { "enabled": false, "lead": "attime" } }`. `lead` ∈ "attime" | "15min" | "1hour".
Items are stored where all widget values are: `fulfillx.entries[date][journal][widgetId]`
holds the item array. Both widget types are addable/editable in Settings → Customize
journals like any other widget (default home for them is the Morning journal).

### Photos (IndexedDB, not localStorage)
Images are too large for localStorage. Use IndexedDB:
- DB `fulfillx`, object store `photos`, key = date string "YYYY-MM-DD", value = a compressed
  image data URL (downscale longest edge to ~1280px, JPEG ~0.8) — one primary photo per day.
- Keep a lightweight index in localStorage `fulfillx.photoIndex` = array of dates that have a
  photo, so the week strip and History grid can render quickly and lazy-load the actual
  image. Update the index whenever a photo is added/removed.

### Backfill / target date
Journals must open for a TARGET DATE, not just today. Add a date parameter to the
open/save/load journal logic (default = today). Saving writes entries under that date.

### Quotes
Replace the V1.0 quote list (which had "Unknown" entries) with the verified set at the
bottom of this spec. Rotate by day-of-year so the quote is stable through the day.

## PHASE 1 — To-Do widgets (checklist + schedule)
Add the `checklist` and `schedule` widget types to the engine and the Settings widget
library. Rendering inside a journal:
- `checklist`: list of tasks with round checkboxes (tap to toggle done, strike-through when
  done); an "+ Add a task" row appends a new item.
- `schedule`: each item shows an optional time pill on the left; items with a time sort
  ascending; items without a time group under an "Anytime" heading; "+ Add" lets you enter
  text and optionally a time. Tap to toggle done.
Both save their item arrays to `fulfillx.entries[date][journal][widgetId]` and reload intact.
Acceptance: both widgets can be added to a journal in Settings, used, saved, and reloaded;
times sort correctly; checkmarks persist.

## PHASE 2 — To-Do quick-access (floating button + sheet)
- A floating action button on Home, ~42px diameter (about 25% smaller than a standard 56px
  FAB), bottom-right, just above the nav, in the theme accent color, with a small badge
  showing the count of unfinished to-do items for today.
- CONDITIONAL: the button only appears when today has at least one to-do item saved (across
  any checklist/schedule widget). No to-do set → no button.
- Tapping it opens a bottom sheet "Today's To-Do" listing today's items aggregated from all
  checklist/schedule widgets: round checkboxes, time pills on timed items, a progress line
  ("2 of 5 done"), and an "+ Add a task" quick-add. Toggling/adding here writes to the SAME
  entry data, so the journal widget and the sheet stay in sync.
Acceptance: button shows only after a to-do exists today; sheet lists today's items with
correct done/time state; changes in the sheet reflect in the journal widget and vice versa.

## PHASE 3 — Reminders (best-effort now, native-ready)
- On `schedule` items that have a time, allow a reminder toggle + lead time (At time /
  15 min before / 1 hour before), stored in the item's `reminder` object.
- Add a one-time Notification permission request when the user first enables a reminder.
- BEST-EFFORT firing while the app is open: a lightweight in-app timer checks upcoming
  reminders and, if permission is granted, shows a Web Notification (and an in-app toast as
  fallback) at the lead time. This is intentionally limited.
- Reliable firing when the app is CLOSED is explicitly OUT OF SCOPE here — it requires the
  native wrapper (Capacitor) milestone. Store the reminder intent fully now so the native
  step can read it later with no rework. Add a short code comment marking where native
  local-notification scheduling will hook in.
Acceptance: reminder toggle + lead time persist on timed items; permission prompt appears
once; while the app is open, a due reminder produces a notification/toast; nothing crashes
if permission is denied.

## PHASE 4 — Photo attachments
- Add IndexedDB photo storage and the `fulfillx.photoIndex` as specified.
- In the Morning and Evening journal screens, add an "Add photo" control (camera/photo
  icon) that lets the user pick an image; downscale/compress and store it as that day's
  photo; show a small thumbnail with a remove option. One primary photo per day.
- Provide helper functions: `getPhoto(date)`, `setPhoto(date, file)`, `removePhoto(date)`,
  and `hasPhoto(date)` (reads the index).
Acceptance: a photo can be added/replaced/removed for a day; it persists across reloads;
storage uses IndexedDB (verify localStorage isn't bloated); the index stays accurate.

## PHASE 5 — History tab + backfill (Option C: month + day detail)
- Add a History tab to the bottom nav (5 tabs: Home / Toolbox / Habits / Insights /
  History — if five feels tight, that's acceptable; do not remove existing tabs without
  asking).
- History view: a compact month grid of round day cells; days with a photo show the photo
  preview, others show the day number; today and the selected day are ringed; prev/next
  month navigation.
- Tapping a day shows a detail card below: the day's photo (if any) and a summary of that
  day's entry — which journals were completed, the Main Goal and whether it was worked
  toward, a reflection snippet, habits completed.
- BACKFILL: tapping a past day with no/partial entry opens that day's journal(s) for THAT
  date (using the target-date logic from the data model) so the user can fill it in or edit;
  saving writes under that past date. Empty days clearly invite a "fill in".
Acceptance: month grid renders with photo previews and navigation; tapping a day shows its
detail; a past day can be opened, filled in, saved, and then shows its entry/photo; today
still works normally.

## PHASE 6 — Home week strip + verified quotes
- Add a Sun–Saturday week strip across the top of Home (below the top bar): each day a
  circle; days with a photo show the preview; the CURRENT day is bolded and ringed.
- Remove the separate date line under the greeting — the strip now carries the date. Keep
  the greeting ("Good morning/afternoon/evening").
- Tapping a day in the strip opens History focused on that day (nice-to-have; fine if it
  just opens History).
- Replace the quote list with the VERIFIED set below. Keep the daily (day-of-year) rotation.
  Do NOT add fabricated or "Unknown" quotes. If you expand the list later, only add genuine,
  correctly attributed quotes; leave a clearly-marked TODO rather than inventing any.
Acceptance: week strip shows the correct days with photo previews and the current day
highlighted; no duplicate date line; quotes come only from the verified list and rotate
daily; both themes intact.
