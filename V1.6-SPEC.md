# FulFillX — V1.6 Specification: Day Metrics + Insights

Builds on the current refactored, multi-file app. Two parts: (A) capture three new day metrics
— Energy, Effort, and Emotions — in the evening; (B) build the Insights page that surfaces
everything (A+C hybrid: clickable stat tiles + soft cards). No build step, no external libraries,
no network, no AI — every number is computed locally from data the app stores. All dates via
localDateKey. Reuse the Slate/Graphite themes, Phosphor icons, the widget engine, and the data
layer. New capture logic lives in journals.js; Insights logic in insights.js.

## HOW TO BUILD THIS
Execute the six phases in order, one at a time, with targeted edits. After each: confirm it
works, summarize, commit ("V1.6 Phase N: <name>"), continue. Never break or discard existing
localStorage / IndexedDB data. Verify both Slate and Graphite, mobile widths.

## GUIDING PRINCIPLES (tone & safety — non-negotiable, carry over from the Insights draft)
- Encouraging and non-judgmental. Celebrate progress; frame gaps kindly; never shame missed days
  or weaponize streaks.
- Observational, never causal ("on days you slept well you tended to…", not "sleep causes…").
- Minimum-data guards: never show a stat or correlation until there's enough data to mean
  something; below threshold show an encouraging "unlocks soon" note instead.
- Emotions are never labeled good/bad to the user. Any internal pleasant/difficult grouping is
  only used to surface gentle, neutral balance observations.
- Keep sensitive counts (cravings, triggers) neutral. No productivity-pressure framing — this
  reflects growth, not optimization.

## PART A — NEW CAPTURES (evening "How was today?")

Add a "How was today?" cluster to the Evening journal (via the widget engine, so it's
customizable). Default it into the evening. Three captures:

1. **Energy** — a 1–10 selector. Prompt: "How much natural energy did you have today?"
   Render as a compact 10-step selector (a slider with a numeric readout, or a compact
   10-button row — whichever is cleaner at phone width). Stored at entries[date].evening.energy.

2. **Effort** — a 1–10 selector (this is the metric formerly called "Activity"). Prompt:
   "How much did you put in today? Reading, studying, and boxing all count." Same 1–10 UI.
   Stored at entries[date].evening.effort.

3. **Emotions** — a NEW multi-select tag widget. Prompt: "What did you feel? Tap any that fit."
   Tags (tappable chips, toggle on/off, multiple allowed), stored as an array at
   entries[date].evening.emotions:
     Happy, Calm, Grateful, Content, Excited, Motivated, Energized, Proud, Hopeful,
     Tired, Drained, Lazy, Anxious, Stressed, Frustrated, Sad, Angry, Lonely, Overwhelmed, Numb
   (The user can edit this list later via customization.) For internal "balance" observations
   only, group these as pleasant = Happy, Calm, Grateful, Content, Excited, Motivated, Energized,
   Proud, Hopeful; difficult = the rest. NEVER show these labels as good/bad to the user.

This emotion capture becomes the app's MOOD source. Retire the old single 4-level daytime emoji
(it's redundant now); keep the daytime check-in's optional one-line note. Don't lose any past
mood data — leave old entries as-is.

Acceptance: Energy and Effort save a 1–10 value; Emotions saves a multi-select array; all reload
intact; both themes fine; the cluster is a normal customizable widget set in the evening.

## PART B — INSIGHTS

### PHASE 2 — Aggregation layer
Pure functions (date-range aware; default last 7 and last 30 days) computing:
- Journaling: days logged; current streak.
- Sleep: avg hours, avg quality (1–5); per-day series.
- Energy: avg (/10); per-day series.
- Effort: avg (/10); per-day series.
- Emotions: frequency per tag over the range; a gentle pleasant/difficult balance.
- Habits: overall completion %; per-habit rate, current + longest streak.
- Goal follow-through: Yes/Partly/No counts of days a goal was set.
- Tools: usage counts; 5 R's counts per craving label; Elephant counts per trigger.
Handle empty/missing data without errors. No UI yet.
Acceptance: functions return correct numbers for known data; safe on empty data.

### PHASE 3 — Insights overview (A+C hybrid)
- A grid of CLICKABLE stat tiles (each a small card: big value, label, tiny trend vs last week,
  a chevron showing it's tappable): Sleep (avg hrs), Energy (/10), Effort (/10), Mood (the 1–2
  most frequent emotions this week — not a number), Habits (%), Goal (x/7). A "Tap any stat for
  the full breakdown" hint under the grid.
- Below the grid, soft cards (style A): 1–3 encouraging "We noticed…" callouts (rule-based, most
  notable first, rotating, min-data guarded) and a chart card (e.g., habits this week).
- Min-data guard: under ~4 logged days this week, show "Your weekly picture fills in as you log
  — keep going" instead of thin numbers.
Acceptance: six tiles show correct values incl. Energy/Effort/Mood; tiles are visibly tappable;
callouts are accurate and encouraging; low-data state shows instead of misleading stats.

### PHASE 4 — Tile drill-downs
Tapping any tile opens its own detail page: the metric's trend over time (lightweight inline-SVG
chart), its day-of-week pattern, and the correlations tied specifically to that stat. The Mood
tile opens an EMOTION view instead: frequency of each emotion over the range (e.g.
"Tired ×12 · Grateful ×9 · Calm ×8"), a neutral balance read, and gentle patterns
("you felt 'Drained' most on days after poor sleep"). Each detail page has a clear Back to
Insights.
Acceptance: every tile opens a correct, themed detail page; Mood opens the emotion-frequency view;
charts render in both themes and degrade gracefully with sparse data.

### PHASE 5 — Patterns & correlations
On the overview's soft cards and within drill-downs:
- Day-of-week patterns: avg habit completion, energy, and mood-balance by weekday — surface the
  strongest and quietest day gently.
- Correlations (observational; require ~10–14 days of overlapping data before showing any; show
  only when the difference is clear):
    energy ↔ sleep, effort ↔ energy, habits ↔ sleep, goal follow-through ↔ habit load,
    emotions ↔ sleep and emotions ↔ habits (e.g. "you felt more energized on higher-habit days").
  Phrase as gentle observations, never causal.
Acceptance: day-of-week patterns shown; correlations appear only past the data threshold, phrased
observationally; nothing implies causation.

### PHASE 6 — Tools insights, empty states, polish
- Tools section: usage counts per tool over the range; 5 R's craving frequency
  ("Smoke ×30 · Beer ×15 · Sugar ×10") and Elephant trigger frequency as neutral counts, tappable
  to the entries; a simple "reflection cadence".
- Thorough, encouraging empty/low-data states across every section; no errors at zero data.
- Verify both themes and mobile widths everywhere.
Acceptance: tools insights show neutral accurate counts; every section has a graceful empty state;
no errors on a fresh install; both themes intact.

## TECH CONSTRAINTS
- Single multi-file app; vanilla JS; no build step. Charts are lightweight inline SVG / CSS only —
  NO chart library, NO CDN (stays offline). Phosphor icons reused.
- Introduces only the new evening capture fields; Insights adds no new storage keys (derives from
  existing data). All dates via localDateKey.
- Targeted edits per phase; never rewrite the whole app in one response. Never break existing data.
